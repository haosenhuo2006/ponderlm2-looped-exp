# s0=0 消融：D3 的 +5.65 NLL 损伤拆分

时间：2026-11-18 晚（D3 之后）。零步评测，不训练。
checkpoint：`runs/reproduction/d3-zero-step`（与 D3 同一 checkpoint、同一验证集 977 块）。
方法：未改任何 `src/` 文件。诊断脚本 `s0_zero_ablation.py` 把 `looped2.sample_s0`
monkeypatch 成返回全零张量，再调官方评测器 `evaluate_looped2` 的
`_load_checkpoint` / `_lm_validation`。除 s0 外一切与 D3 相同。

## 结果

| 组 | r | NLL | 相对底座 4.3733 的损伤 |
|---|---|---|---|
| 随机 s0（D3） | 1 | 12.0266 | +7.65 |
| s0=0（本消融） | 1 | 9.1932 | +4.82 |
| 随机 s0（D3） | 4 | 10.0225 | +5.65 |
| s0=0（本消融） | 4 | 9.6375 | +5.26 |

## 拆分（r=1，干净分解）

r=1 时 s0=0 的 core 输入就是干净的 prelude 输出 e，所以：

- 随机初态 s0 部分 = 12.0266 − 9.1932 = **2.83**（占 r=1 总损伤 7.65 的 37%）
- sandwich 部分 = 9.1932 − 4.3733 = **4.82**（占 63%）

r=4 时：去掉噪声只挽回 10.0225 − 9.6375 = 0.39，残留损伤 +5.26 几乎全是结构部分。

## 一致性检查：r 的变化方向反过来了

- 随机 s0：r=1（12.03）→ r=4（10.02），轮次越多越好——每轮重新注入干净的 e，把噪声稀释了。
- s0=0：r=1（9.19）→ r=4（9.64），轮次越多越差——没有噪声可稀释，重复经过 sandwich 结构的 core 反而把信号越带越偏。

两个方向相反，说明两部分损伤都是真实、独立的，也说明 monkeypatch 确实生效了
（若未生效，s0=0 的 r=1 会等于随机的 12.03）。

## 注意：sandwich 部分是捆绑的

9.1932 − 4.3733 = 4.82 不只是 sandwich norms 的并行→串联改动，还捆绑了
core 边界多用一次 `final_layer_norm`（A3，vanilla 只在最后用一次）。两者都是
"改初态修不了"的结构性改动，拆分到这一步已足够做裁决；再细拆需要另做消融。

## 结论：只改初态救不了 L1

- 最好的初态修复（s0=0）在评测深度 r=4 也只剩 +5.26 的坑，1200 步 CPT 几乎不可能填上
  （旧 looped 从 +1.01 的坑出发、1200 步也只爬回来 0.76）。
- 损伤的大头（r=1 时 63%，r=4 时约 93%）是 sandwich 结构改动，不是初态。
- 因此 D3 三条路里"改初态设计"单独走不通；要救 L1 得连 sandwich 结构一起重新设计
  （那是超出冻结预注册的大改动），或者接受 L1 大概率白烧。
- 从零训臂（L2/A1/Yang）不受影响：权重从头学着用 sandwich 结构，没有预训练权重可毁。
