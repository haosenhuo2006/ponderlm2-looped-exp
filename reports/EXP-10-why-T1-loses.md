# EXP-10 — 诊断分析：T1 为什么在 tiny-scale 下输给 vanilla

## 0. 范围与证据

本篇不是新训练实验，而是一篇**基于 EXP-01 至 EXP-09 全部结果**的诊断分析。问题：完整 PonderLM-2（T1）在本系列 tiny-scale 设置下为什么输给普通 LM（T0）？

设置（全部实验共用）：Pythia-70M 预训练底座、WikiText-2、seq 256、600 步（2,457,600 输入 tokens）、AdamW lr 1e-4、seed 42 为主种子；EXP-08 补了 seed 43、44。

证据总表（主验证 NLL，WikiText-2 validation；EXP-08 为三种子均值 ± 样本标准差）：

| 模型 | seed 42 | 三种子均值 ± SD | 备注 |
|---|---:|---:|---|
| T0 vanilla | 4.9271 | 4.900 ± 0.040 | 最好 |
| T6 每轮立刻更新（EXP-07） | 5.1903 | 单种子 | 1494 次更新，见 H1 |
| T4 Looped | 5.4855 | 5.775 ± 0.309 | seed 43 翻转，见下 |
| T2 无前序 h | 5.8107 | 5.808 ± 0.081 | 三种子稳定赢过 T1 |
| T5 中间监督 | 5.8356 | 单种子 | 汇总后统一更新 |
| T1 完整 PonderLM-2 | 6.0070 | 6.041 ± 0.061 | 第二差 |
| T3 历史走 h | 6.4069 | 单种子 | 最差 |

关键差值（EXP-08，三种子）：T1−T0 = +1.14（+/+/+，方向稳定）；T2−T1 = −0.23（−/−/−，方向稳定）；T4−T1 = −0.27 均值但符号翻转（−/+/−，seed 43 为 +0.09）。

其他证据：
- EXP-02 推理诊断（T1 checkpoint）：D1 屏蔽前序 h，NLL 6.0070 → 6.1612（+0.1542），top-1 一致率 49.43%；D2 屏蔽历史 x，NLL → 7.2682（+1.2613），top-1 一致率 34.64%。
- EXP-06 逐轮 NLL（固定 K=3）：T1 为 6.1448 → 6.0070 → 6.0078；T5 为 5.8416 → 5.8414 → 5.8369。T1 的 round-1 明显差于 round-2/3，T5 三轮几乎拉平。
- EXP-07 逐轮 NLL（固定 K=3）：T6 为 5.1773 → 5.1923 → 5.1906，非单调；最终预测 5.1903。T6 训练耗时 1147.59 s（T1 905.81 s、T5 763.25 s，均为历史计时、非同步配对）。
- Jacobi 收敛（EXP-01，T1 checkpoint）：bf16 下 d_k 在 round 3–8 plateau 于约 0.11–0.15；同一 checkpoint 的 FP32 诊断 round-8 r_k = 0.000184、d_k = 0.000199。
- EXP-09 下游（seed 42）：ARC-Easy validation 570 题，T0 26.67%、T1 24.91%、T2 25.79%、T4 25.44%、T5 25.09%；LAMBADA 前 500 条单 token 子集 229 条，T0 3.93%（9/229）、T1 0%、T2 0%、T4 0.44%、T5 0.44%。

## 1. 假设 H1：优化不足——相同 token/步数预算下，thought 机制没训够（最强解释）

**内容**：PonderLM-2 每 token 要多算一次（推理约 2× FLOPs，训练约 8×），但本系列固定了训练 token 数（2.46M）和优化器步数（600 步）。T1 在同样预算下既要适应预训练权重，又要从头学会“用 thought 预测”这套新计算，优化量相对其任务更少。差距首先是**预算口径**问题，其次才是架构问题。

**支持证据**：
- 差距远大于种子噪声：T1−T0 = +1.14 NLL，而 T0、T1 的三种子标准差分别只有 0.040 和 0.061。EXP-08 已排除“单种子噪声”这一解释。
- 只改变监督/更新方式就能大幅缩小差距：T5（每轮 CE 取均值、汇总后统一更新）相对 T1 为 −0.17；T6（每轮 CE 各自反向、各更新一次）相对 T1 为 −0.82、相对 T5 为 −0.65。架构、数据、token 预算全都没变，只动了“怎么监督、什么时候更新”。
- T1 的逐轮 NLL 显示早期轮次明显欠训：round-1 为 6.1448，比 round-2/3 差约 0.14；而 T5 的三轮几乎拉平。说明 T1 的训练信号没能有效教会早期轮次。
- 预算量级对照：论文的从头训练用 26B tokens、继续预训练用 5B tokens；本系列只用了 2.46M tokens，相差约四个数量级（从头口径）到三个数量级（CPT 口径）。在这个预算下要求一个新机制从头学会，是很苛刻的。

**反对/限定证据**：
- T6 的改进混杂了三个变化，不能单归因于“更新时机”：T6 相对 T1 同时改变了（a）监督方式（每轮 CE，而 T1 只监督最终轮）、（b）更新次数（1494 次 vs 600 次）、（c）梯度截断（轮间 detach，梯度不再穿过前面轮次）。其中更新次数一项单独就可能解释大部分改进。**T6 的 5.19 不能读作“导师的每轮更新想法被证实了”，只能读作“监督+更新次数+截断这组改动合起来有效”。**
- 即使是 T6（5.19）仍然输给 T0（4.93）约 0.26 NLL。优化不足可以解释“差距为什么这么大”，但不能单独解释“为什么 thought 机制本身没能反超”——H2 的机制成本仍需考虑。

**置信度**：强。作为“差距主因”的最佳单一解释，但需 H2 补充。

## 2. 假设 H2：序列内插 thought 的分布偏移与容量竞争（中强解释）

**内容**：PonderLM-2 把 h 插进序列，使每个真实 token 后多一个 latent 位置，序列长度翻倍、position id 复用。预训练 70M 模型从未见过这种输入：它必须在 600 步内学会把“每隔一个位置是连续向量”当作正常输入，同时用这些位置完成预测。thought 位置还要与真实 token 竞争 attention 容量。这是一种**机制本身的成本**，与优化量无关（但会随训练预算增加而摊薄）。

**支持证据**：
- 去掉前序 h 的通路反而更好，且三种子稳定：T2−T1 = −0.23（−/−/−）。如果前序 h 的信息传递是收益的主要来源，去掉它应该变差；实际变好，说明在本设置下“前序 h 参与后续计算”这条通路的净效应是负的——成本大于收益。
- D2 诊断：屏蔽历史 x 后，模型只靠 h 传递历史，NLL 恶化 +1.26，top-1 一致率只剩 34.64%。h 承载历史信息的能力很弱，与皓森 11/9 日志里的怀疑一致。
- 下游 LAMBADA 上 T1/T2 均为 0%（T0 为 3.93%）：不只是 WikiText-2 NLL 变差，长上下文末词预测能力也跌到地板。这与“thought 机制挤占了通用语言建模能力”一致（但须注意 LAMBADA 样本小、绝对值接近地板，见局限性）。
- T4（深度方向循环、不插 thought 位置）在三种子均值上好于 T1（5.775 vs 6.041），与“插位置比循环层更贵”相符；但 T4 存在种子翻转，该条证据较弱。

**反对/限定证据**：
- 论文在 410M–1.4B、26B–300B tokens 上证明了该机制可以work，说明 H2 描述的不是机制本身的不可能，而是**规模/预算依赖性**：小模型 + 极小预算下成本占优，大模型 + 大预算下收益占优。本系列无法区分“机制在小规模下本质更差”与“只是还没训够”。
- T2 仍然输给 T0 约 0.91 NLL。去掉前序 h 只挽回了 0.23，剩下的差距来自“当前 h 的额外计算”本身（生成 h、再喂回去预测）或 H1 的优化不足。H2 不能单独解释全部差距。
- D1 推理诊断与 T2 训练结果方向相反：T1 上屏蔽前序 h 会变差（+0.15），但从训练起就屏蔽的 T2 反而比 T1 好。这说明“已有模型依赖前序 h”与“从训练起就不需要前序 h”是两回事，H2 的表述须限定在训练口径。

**置信度**：中强。作为 H1 之外的必要补充解释。

## 3. 假设 H3：Jacobi 训练–推理不一致或收敛问题（弱，基本排除为主因）

**内容**：训练用并行 Jacobi 近似顺序生成，推理用顺序计算；如果 Jacobi 不收敛或 bf16 数值噪声大，训练目标与推理行为就会脱节，导致 T1 在推理评测时吃亏。

**证据（主要是否定性的）**：
- FP32 诊断：同一 T1 checkpoint 上，round-8 的 r_k = 0.000184、d_k = 0.000199，Jacobi 实际上收敛到了顺序计算结果。训练–推理不一致不是主因。
- bf16 下 d_k plateau 在约 0.11–0.15，是数值精度 floor，不是“迭代没收敛”——r_k 同样 plateau，说明相邻轮次的状态已不再变化，只是与顺序结果之间存在一个 bf16 噪声地板。评测本身也用固定 K=3 的同一协议，训练与评测的计算方式是一致的。
- 顺序子集 NLL（5.898）反而好于并行验证 NLL（6.007），不一致的方向很小，且有利于 T1 而非有害。

**仍有待排除的次要因素**：
- K ∈ {2,3} 随机采样 + 只有 600 步，模型见过的 refinement 轨迹总数很少；bf16 噪声在训练过程中的累积效应没有单独测过。这两项未被排除，但即使存在，其量级也难以解释 1.14 NLL 的差距。

**置信度**：弱。作为主因基本排除；作为次要因素保留。

## 4. 已排除的解释

- **单种子噪声**：EXP-08 已排除。T1−T0 = +1.14，而各模型三种子标准差 ≤ 0.09（T4 除外）。
- **Jacobi 不收敛**：FP32 诊断已排除（见 H3）。
- **评测口径错误**：EXP-06 的最终预测 logit 与官方路径 parity 在 1e-6 内；各实验均有受保护文件校验（EXP-08 同理）。T1 的 NLL 不是算错的。
- **T1 没训完（loss 发散/NaN）**：各实验训练 loss 均有限、无 OOM、无静默截断。T1 训完了，只是训出的结果差。

## 5. 未排除、需要新实验的问题（按优先级）

1. **计算预算匹配的 T0 vs T1**（最优先）：固定训练 FLOPs 而非固定 tokens，让 T0 训练更久/更多 tokens，看 T1−T0 的差距是否缩小。现有比较是“相同 tokens”，而 PonderLM-2 每 token 的训练成本约 8×，该口径天然不利于 T1。
2. **隔离 T6 的更新次数混杂**：以下任一对照——（a）T1 目标 + 1494 次更新（例如把 T1 的步数/epoch 结构改成与 T6 相同的更新次数，token 预算不变）；（b）T6 目标但把总更新次数压回 600 次。区分“更新次数”与“更新时机/监督方式”的贡献。
3. **延长训练/扩大数据**：600 → 1200/2400 步，看 T1−T0 差距是否随预算单调缩小。预算翻倍的成本在单卡上可接受（T1 约 15 分钟/600 步）。
4. **放大底座**：Pythia-160M 或 410M，检验 H2 的规模依赖性。先做显存/耗时测算（410M 在 8GB 上 batch 1、seq 256 应可跑，但须实测），测算写进报告再决定跑不跑。
5. **T5/T6 多种子 + 下游复核**：T6 的 5.19 目前是单种子，且其下游表现未知；T4 的种子翻转已经说明单种子结论不可靠。
6. **h 的信息内容探针**（论文附录 J 式）：把 T1/T2 的 latent 过 lm_head 解码，看 h 是否编码可读的预测信息、与最终输出 top-1 的重合率。这直接检验“h 是假设还是噪声”。

## 6. 一句话结论

最可能的完整解释是 **H1 + H2 的组合**：在只有 2.46M tokens、600 步的预算下，thought 机制既没训够（监督信号弱、更新次数少），又要支付序列内插带来的分布偏移与容量竞争成本；Jacobi 本身收敛良好，不是主因。论文规模下收益占优、小规模下成本占优，是预算与规模依赖性的表现，不是机制本身的证伪——但本系列的证据也不支持“只要多训一点 thought 就一定反超”，需要实验 1–3 来检验差距是否随预算缩小。

## 7. 本篇局限性

- 本篇没有新训练实验，结论是对已有实验的推断，不是新的因果证据；H1/H2 的相对权重无法从现有数据中分离。
- T3/T5/T6 仍是单种子；T6 的下游表现未知；LAMBADA 绝对值接近地板（T0 仅 3.93%），下游结论的统计力度弱。
- 全部结论限于 Pythia-70M + WikiText-2 + 600 步的 tiny-scale 设置，不能外推到论文规模。
- FLOPs 均为解析估计，非 profiler 实测；训练耗时为历史计时、非同步配对。
